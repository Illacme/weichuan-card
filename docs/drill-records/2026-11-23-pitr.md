## 演练环境

| 项 | 值 |
|---|---|
| 数据库 | `mysql:8.0`，启动参数 `--log-bin=/var/lib/mysql/mysql-bin --server-id=1 --binlog-format=ROW` |
| 探针数据 | `pitr_probe(id, note)`：基线 A1/A2 → 全量备份 → 备份后写 B1 → `DELETE` 全表 |
| 全量备份 | `mysqldump` → gzip（`gzip -t` 校验） |
| binlog | `FLUSH BINARY LOGS` 封口 → `docker cp` → gzip（`gzip -t` 校验） |
| 回放 | 宿主机 `mysqlbinlog 9.3`，`--start-position=157 --stop-position=455 --rewrite-db=weichuan_pitr->weichuan_pitr_restore` |
| 命令 | `bash scripts/restore_pitr_drill.sh` |

## 校验项

| 项 | 结果 |
|---|---|
| 全量备份包 gzip -t | PASS |
| binlog 归档 gzip -t | PASS |

## 边界（不要过度解读）

- 这次演练的是**隔离容器里的探针表**，不是生产库；它证明的是「归档 → 回放 →
  定点跳过」这条链路的行为，不替代**在真实归档上**按真实误操作时间点做的那次演练
  （`docs/launch-checklist.md` 第 9 项仍是运维待办）。
- 生产要做到 PITR，仍必须开 binlog 并按小时跑 `scripts/backup_binlog.sh`；
  SQLite 形态没有 binlog，没有 PITR。
- `mysqlbinlog` 在宿主机执行（mysql:8.0 官方镜像不带这个客户端），可用
  `MYSQLBINLOG` 环境变量指向自装版本。
