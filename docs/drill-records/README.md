# 恢复演练记录

本目录存**每次恢复演练的输出**，文件名 `YYYY-MM-DD-<形态>.md`。
`scripts/restore_drill.sh` 会在结尾直接打印可粘贴的正文（「留档正文」一段），
不用回头手工整理——靠人去「事后补记」的记录，最后通常就没有记录。

为什么留档：备份这东西**不演练过就等于没有**。而「我们演练过」这句话，
在没有记录的时候是无法向客户 / 审计 / 半年后的自己证明的。

| 时间 | 形态 | 备份文件 | 结论 | 记录 |
|---|---|---|---|---|
| 2026-10-27 | SQLite | `weichuan-20261027-014210.db.gz` | ✅ 通过 | [2026-10-27-sqlite.md](./2026-10-27-sqlite.md) |
| 2026-10-27 | MySQL | `weichuan-20261027-014614.sql.gz` | ✅ 通过 | [2026-10-27-mysql.md](./2026-10-27-mysql.md) |

节奏：**每季度至少一次**，并在下列任一情况后补跑一次——升级数据库迁移之后、
改过备份脚本之后、换了部署形态之后。演练不通过时不要只改脚本，要回头查
「为什么会不通过」：备份链路坏了却没人发现，是最典型的「以为有备份」。
