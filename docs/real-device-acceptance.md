### 0.1 《用户隐私保护指引》声明（最关键，漏一项就 errno 112）

路径：登录 → 设置 → 基本设置 → 服务内容声明 → 用户隐私保护指引（更新）。

代码里实际调用的隐私接口与**必须声明**的权限类型（对照 `utils/privacy.ts` 与调用点核实）：

| 权限类型（MP 后台名称） | 对应接口 | 代码调用点 | 漏声明的后果 |
|---|---|---|---|
| 剪切板（写入你的剪切板） | `wx.setClipboardData` | `components/employee-card`（复制联系方式）、`pages/mydata`（复制数据） | 复制按钮点了 fail |
| 通讯录（仅写入）权限 | `wx.addPhoneContact` | `pages/index`（存入通讯录） | **2026-10-30 真实事故**：未声明 → `errno 112` 死循环「需要隐私授权」 |
| 相册（仅写入）权限 | `wx.saveImageToPhotosAlbum` | `pages/poster`（保存海报） | 存相册按钮 fail |
| 选择的照片或视频信息 | `wx.chooseMedia` | `pages/poster`（换海报背景）、`pages/employee/edit`（换头像）、`pages/apply/open`（申请头像） | 选图器打不开 |
| 摄像头 | `wx.chooseMedia`（未传 `sourceType`，默认含相机拍摄） | 同上三处 | 拍摄入口 fail |

- `wx.login` **不在**隐私接口表内（静默接口，不需要授权弹窗），但指引正文里仍要按 MP 后台要求
  声明 openid 所属的「用户标识信息」——这是两件事，别混为一谈。
- `getUserProfile` 已收回，头像昵称用 `<input type="nickname">`，无需声明。
- 指引里的「使用的场景/目的」如实填：复制联系方式、存入通讯录、保存海报、更换头像等。
- 提交后需**审核**（通常 1~2 个工作日），期间可先做 0.2~0.4 和不涉隐私的验收项。

### 0.5 服务器域名与 WX 凭据（真机首跑前必核）

- [x] **request 合法域名**含该域名：`wx.request`（`/api/card`、`/api/public/settings`、埋点等）
- [x] **uploadFile 合法域名**含该域名：`wx.uploadFile`（申请头像 `apply/open`、
      员工换头像 `employee/edit`、海报换背景 `poster`）
- [x] **downloadFile 合法域名**含该域名：海报页 `canvas.createImage()` 加载背景图与小程序码。

      （`poster.ts:1457`）——这是失败态，不是白屏，但容易被当成「码没生成」
- [x] **WX 凭据可用**：后台「系统设置 → 微信」或环境变量 `WX_APPID` / `WX_APPSECRET` 已配对。
      判据：管理端点一次「生成小程序码」能出图。没配则 §3 的海报二维码与 §4.1 的微信登录都会卡住
